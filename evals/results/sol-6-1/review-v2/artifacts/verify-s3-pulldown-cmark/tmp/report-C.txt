P0110 Found **19 behavior/build issues**. The existing package tests pass; targeted local regressions expose the following gaps. All behavior findings below were executed against the unchanged release source.

P0111 CLI processing repeats earlier files — [main.rs:173](/work/crate/pulldown-cmark/src/main.rs:173). `read_to_string` appends to the same buffer for every filename. Files containing `one\n` and `two\n` produce `<p>one</p>\n<p>one\ntwo</p>\n`, duplicating the first document. Each file should be rendered once.

P0112 CLI I/O failures return success — [main.rs:184](/work/crate/pulldown-cmark/src/main.rs:184), [main.rs:219](/work/crate/pulldown-cmark/src/main.rs:219). Invalid UTF-8 on stdin produces empty output, no diagnostic and exit status 0. Writing to a closed output pipe also exits 0. Read/write failures should propagate so callers can detect lost input or output; buffered output also needs an explicit checked flush.

P0113 Linking a wiki image corrupts its destination — [parse.rs:642](/work/crate/pulldown-cmark/src/parse.rs:642). With `ENABLE_WIKILINKS`, `[![[foo.png]]](bar)` should produce an image linking to `bar`. Instead it produces `<p>[<img src="bar" alt="](bar)" /></p>`. The successful wikilink path leaves regular bracket-stack entries available for subsequent parsing, allowing the image node to be overwritten.

P0114 Uppercase HTML closing tags fail to end blocks — [firstpass.rs:1250](/work/crate/pulldown-cmark/src/firstpass.rs:1250). CommonMark requires case-insensitive matching here, but termination uses case-sensitive `contains`. For `<pre>\nx\n</PRE>\n*after*\n`, `*after*` remains raw HTML-block content instead of becoming an emphasized paragraph. Subsequent document content can be misparsed.

P0115 Tabs prevent code fences from closing — [scanners.rs:528](/work/crate/pulldown-cmark/src/scanners.rs:528). CommonMark permits spaces or tabs after a closing fence; this scanner accepts only spaces. For `"```\nx\n```\t\nafter\n"`, the closing fence and `after` remain inside the code block instead of ending it and starting a paragraph.

P0116 Case-insensitive footnote matching produces broken links and numbering — [html.rs:138](/work/crate/pulldown-cmark/src/html.rs:138). The parser accepts `[^A]` and `[^a]` against definition `[^a]: definition` through case-folded lookup. The renderer nevertheless emits targets `#A` and `#a`, numbers them 1 and 2, and labels the sole definition 2. Both references should share a number and resolve to the same definition.

P0117 The `getopts` feature can select an unbuildable binary — [main.rs:25](/work/crate/pulldown-cmark/src/main.rs:25). The binary requires `getopts` in the manifest but unconditionally imports feature-gated `html`. `cargo check --locked -p pulldown-cmark --no-default-features --features getopts` fails with E0432. The binary’s feature requirements should include its HTML dependency.

P0118 An unmatched caret cancels valid strikethrough — [parse.rs:1614](/work/crate/pulldown-cmark/src/parse.rs:1614). Carets and tildes share a delimiter-search lower bound. With superscript and strikethrough enabled, `~~a b^ c~~` renders literally; it should render `<del>a b^ c</del>`. Attempting to close unmatched superscript incorrectly excludes an existing tilde opener.

P0119 Broken-link callback overrides references that already have definitions. pulldown-cmark/src/parse.rs:343. Parser::new_with_broken_link_callback invokes the supplied resolver even after finding an in-document reference definition. A callback that always supplies /fallback therefore replaces the destination and title of [ok][known] despite [known]: /defined "Defined" being present. Applications using a callback to fill missing links also rewrite links explicitly authored in the document.

P0120 Subscript alone suppresses unrelated inline parsing — [parse.rs:993](/work/crate/pulldown-cmark/src/parse.rs:993). With only `ENABLE_SUBSCRIPT`, `~~*a*~~`, `~~[a](b)~~` and ``~~`a`~~`` all render literally. Unsupported double-tilde delimiters should remain text while their contents retain ordinary emphasis, link and code parsing. Creating a text node with children causes those children to be skipped.

P0121 CRLF becomes two spaces inside code spans — [parse.rs:1340](/work/crate/pulldown-cmark/src/parse.rs:1340). CommonMark treats CRLF as one line ending. `` `a\r\nb` `` yields code text `a  b`, whereas LF and CR versions yield `a b`. Each byte is replaced separately, changing code content in ordinary Windows-format documents.

P0122 CR-only line endings break block parsing — [scanners.rs:508](/work/crate/pulldown-cmark/src/scanners.rs:508). `scan_nextline` searches only for LF, although CommonMark also recognizes standalone CR. For example, `"    x\r\rafter\r"` becomes one code block containing `after`, rather than a code block followed by a paragraph. Fenced-code and HTML-block probes also fail; LF and CRLF controls pass.

P0123 Wikilink source ranges omit the final bracket — [parse.rs:944](/work/crate/pulldown-cmark/src/parse.rs:944). `[[page]]` has eight bytes, but its start/end link events report `0..7`. Piped links and wiki images have the same error. The documented corresponding-source-range contract requires the complete construct; source-based editing can otherwise leave a stray bracket.

P0124 Reference-label length counts bytes incorrectly — [linklabel.rs:122](/work/crate/pulldown-cmark/src/linklabel.rs:122). CommonMark permits at most 999 characters. Ordinary ASCII characters are not counted, while every non-ASCII UTF-8 byte is counted. A 1,000-character ASCII label is accepted; valid labels containing 500 `é` characters or 334 `界` characters are rejected, leaving links and definitions as literal text.

P0125 Tabs are not trimmed around ATX closing markers — [firstpass.rs:1655](/work/crate/pulldown-cmark/src/firstpass.rs:1655). CommonMark permits tabs around closing hashes and strips trailing tabs. Both `# heading\t###` and `# heading ###\t` retain literal hashes in the heading. The trimming logic recognizes spaces only.

P0126 Nested inline end tags prematurely terminate image alt-text collection. pulldown-cmark/src/html.rs:484. HtmlWriter::raw_text stops collecting an outer image description when it reaches the end of nested emphasis or a nested image. For ![before *em* ![inner](inner.png) after](outer.png) tail, this closes the outer alt attribute too early and renders the remaining description as ordinary page text. Image descriptions containing nested inline markup consequently lose their trailing alt text.

P0127 Tabs incorrectly create hard line breaks — [firstpass.rs:849](/work/crate/pulldown-cmark/src/firstpass.rs:849). Hard breaks require two spaces or a backslash, but the implementation counts all non-newline ASCII whitespace. `foo\t\t\nbar`, `foo \t\nbar` and `foo\t \nbar` each produce `<br />` instead of a soft break, changing document layout.

P0128 Valid HTML with tab-separated unquoted attributes is escaped — [scanners.rs:452](/work/crate/pulldown-cmark/src/scanners.rs:452). Tabs must terminate an unquoted attribute value. For `a <b x=one\ty=two>z</b>`, the opening tag becomes `&lt;b x=one\ty=two&gt;` while the closing tag remains HTML. Valid embedded markup is rendered as text because the value scanner consumes the tab.

P0129 Invalid table alignment syntax becomes a table — [scanners.rs:675](/work/crate/pulldown-cmark/src/scanners.rs:675). The bundled GFM contract permits colons only at delimiter-cell edges. A delimiter cell `-:-` is nevertheless accepted as right-aligned. Ordinary prose or an incomplete table containing that sequence is converted into a table instead of remaining text.

P0130 Single-character valueless heading attributes disappear — [firstpass.rs:2548](/work/crate/pulldown-cmark/src/firstpass.rs:2548). With heading attributes enabled, `# heading {a bb c=d}` emits `bb="" c="d"` but drops `a`. The documented custom-attribute syntax does not impose a two-character minimum. Callers silently lose an explicitly supplied attribute.

P0131 Tabbed fence metadata leaks into the language class — [html.rs:261](/work/crate/pulldown-cmark/src/html.rs:261). The renderer’s first-word language convention splits only on spaces. A fence with info `rust\tmore` produces `class="language-rust\tmore"` instead of `class="language-rust"`, turning following metadata into an additional HTML class. This is a smaller renderer-consistency issue.
