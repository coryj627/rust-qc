P0088 Found **14 correctness/build issues**. The existing test suites pass, but added local regressions reproduce the failures below. All behavioral findings are supported by executed tests and source inspection.

P0089 HTML blocks ignore valid closing tags. [firstpass.rs:1250](/work/crate/pulldown-cmark/src/firstpass.rs:1250) uses a case-sensitive search for the opening tag’s corresponding closing tag. CommonMark permits case-insensitive closing tags and, for these blocks, does not require matching tag names. Both `<script>\nx\n</SCRIPT>\n\nafter` and `<pre>\nx\n</style>\n\nafter` incorrectly absorb `after` into the HTML block instead of emitting `<p>after</p>`. Ordinary documents can lose Markdown rendering for their remaining content.

P0090 Table rows with missing trailing cells emit too few cells. pulldown-cmark/src/firstpass.rs:519. parse_table_row_inner returns a short body row after scanning only the cells physically present on its line, without adding the missing trailing cells required by the table header. With ENABLE_TABLES, a three-column table followed by the body row | one | emits one TableCell and renders only one td rather than three. Consumers that depend on a consistent column count receive ragged event rows and HTML.

P0091 A trailing tab prevents a code fence from closing. [scanners.rs:528](/work/crate/pulldown-cmark/src/scanners.rs:528) accepts only spaces after closing backticks. CommonMark permits spaces or tabs. For `"```\nx\n```\t\nafter"`, the closing fence and `after` become code content. A trailing editor-inserted tab can therefore change the rest of a document’s structure.

P0092 The CLI renders previous files again when given multiple files. [main.rs:173](/work/crate/pulldown-cmark/src/main.rs:173) appends every file to the same `String`, then renders that accumulated string on every iteration. Files containing `"one\n"` and `"two\n"` produce:
   ```html
   <p>one</p>
   <p>one
   two</p>
   ```
   Expected behavior is to render each input once. Batch callers receive duplicated content and potentially changed Markdown structure.

P0093 The CLI silently discards I/O failures. [main.rs:184](/work/crate/pulldown-cmark/src/main.rs:184) ignores stdin read errors; [main.rs:219](/work/crate/pulldown-cmark/src/main.rs:219) ignores rendering/write errors. Tests supplying invalid UTF-8 through stdin and closing the stdout pipe both observed exit status **0**, with no diagnostic. Callers cannot distinguish successful conversion from missing output.

P0094 Case-insensitive footnote references produce inconsistent anchors and numbers. [html.rs:141](/work/crate/pulldown-cmark/src/html.rs:141) and [html.rs:382](/work/crate/pulldown-cmark/src/html.rs:382) use the original, case-sensitive label strings, although parser lookup folds case. With `a[^NOTE] b[^note]\n\n[^Note]: text\n`, the references target `#NOTE` and `#note`, numbered 1 and 2; the definition has ID `Note`, numbered 3. Recognized references should share a number and resolve to their definition. Instead, ordinary case variations produce broken navigation.

P0095 CRLF becomes two spaces inside code spans. [parse.rs:1340](/work/crate/pulldown-cmark/src/parse.rs:1340) processes CR and LF separately. CommonMark defines CRLF as one line ending, replaced by one space in code spans. Parsing `` `a\r\nb` `` produces `<code>a  b</code>` instead of `<code>a b</code>`. This changes literal code content in Windows-formatted Markdown.

P0096 Several block parsers do not recognize CR-only line endings. [scanners.rs:508](/work/crate/pulldown-cmark/src/scanners.rs:508) searches only for LF. CommonMark also recognizes standalone CR. For example, `"```rust\rx\r```"` becomes a paragraph followed by an empty code block instead of a Rust code block containing `x`. Indented blocks also retain subsequent indentation incorrectly. Equivalent supported line endings should preserve document structure.

P0097 The `getopts` feature can select a binary that cannot compile. [main.rs:25](/work/crate/pulldown-cmark/src/main.rs:25) imports `html` unconditionally, while [Cargo.toml:27](/work/crate/pulldown-cmark/Cargo.toml:27) requires only `getopts` for the binary. `cargo check --locked -p pulldown-cmark --no-default-features --features getopts` fails with E0432 because `html` is disabled. The same configuration with `--lib` passes, isolating the failure to binary feature configuration.

P0098 Link-label length counting rejects valid Unicode labels and accepts oversized ASCII labels. [linklabel.rs:122](/work/crate/pulldown-cmark/src/linklabel.rs:122) increments the character count for each non-ASCII byte and skips ordinary ASCII characters. CommonMark permits at most 999 Unicode code points. A reference label containing 500 `é` characters fails to resolve, while one containing 1,000 ASCII `a` characters resolves. Controls with 499 `é` and 999 ASCII characters pass.

P0099 Wikilink source ranges omit the final bracket. [parse.rs:944](/work/crate/pulldown-cmark/src/parse.rs:944) sets the end offset one byte too early. For `[[page]]`, the link’s range selects `[[page]`. `into_offset_iter()` promises the corresponding Markdown source range; editors and source transformations using this range leave a closing bracket behind.

P0100 Repeated footnote references consume new display numbers. pulldown-cmark/src/html.rs:139. The FootnoteReference rendering arm calculates the next number on every occurrence and assigns it even when the label has already been seen. With ENABLE_FOOTNOTES, first[^a] second[^a] third[^b] and definitions for a and b therefore display reference numbers 1, 2, 3 rather than 1, 1, 2. Repeating a reference changes the displayed identity of the same footnote and shifts numbering for later notes.

P0101 ATX heading closers mishandle tabs. [firstpass.rs:1655](/work/crate/pulldown-cmark/src/firstpass.rs:1655) and [firstpass.rs:1664](/work/crate/pulldown-cmark/src/firstpass.rs:1664) trim/check spaces without tabs. CommonMark permits tabs around closing hashes. `"# foo\t###\t\n"` renders `<h1>foo\t###\t</h1>` instead of `<h1>foo</h1>`, exposing syntax characters as heading content.

P0102 Inline links accept a title without the required separator. [parse.rs:1156](/work/crate/pulldown-cmark/src/parse.rs:1156) attempts title parsing even when no whitespace follows a nonempty destination. CommonMark requires separation between destination and title. `[a](<url>"title")` incorrectly emits a link with destination `url` and title `title`; it should not emit a link. The whitespace-separated control behaves correctly.

P0103 Subscript parsing can disable unrelated superscript parsing. [parse.rs:1596](/work/crate/pulldown-cmark/src/parse.rs:1596) and [parse.rs:1614](/work/crate/pulldown-cmark/src/parse.rs:1614) share a delimiter-search lower bound between carets and tildes. With superscript alone, `^a b~ c^` produces `<sup>a b~ c</sup>`. Enabling subscript as well makes the entire expression literal. An unmatched tilde should not invalidate the independent caret pair; combining documented extensions changes otherwise valid formatting.

P0104 Single-character heading attributes disappear. [firstpass.rs:2548](/work/crate/pulldown-cmark/src/firstpass.rs:2548) skips every attribute token of length one. The public heading-attribute contract permits custom attributes without values. With `ENABLE_HEADING_ATTRIBUTES`, `# hi {x}` should retain `("x", None)`, but emits an empty attribute list. Callers silently lose requested metadata.
