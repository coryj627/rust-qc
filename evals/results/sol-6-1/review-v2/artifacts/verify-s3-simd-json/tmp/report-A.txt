P0003 NEON stores assume alignment that `Vec<u32>` does not guarantee

P0004 [src/impls/neon/stage1.rs:207](/work/crate/src/impls/neon/stage1.rs:207), store at line 226.

P0005 The SIMD store requires 16-byte alignment. The implementation chooses `ptr::write` based on the element offset being divisible by four, although the allocation itself only guarantees four-byte alignment.

P0006 Executed evidence: the existing `value::tape::array::test::get_nested` test fails under Miri with “alignment 4, but alignment 16 is required.” This affects ordinary parsing on aarch64.

P0007 use an unaligned store or guarantee the allocation’s alignment.

P0008 Nested tape accessors truncate containers and can panic

P0009 [src/value/tape/trait_impls.rs:425](/work/crate/src/value/tape/trait_impls.rs:425); also lines 454, 487 and 519.

P0010 The returned slice must include the container header and every descendant node. These accessors use the descendant count without adding the header.

P0011 Executed evidence:

P0012 - `{"a":[1,2]}`: `get_array("a")` iterates only `1`.
- `{"o":{"a":1,"b":2}}`: `get_object("o")` iterates only `"a"`.
- Empty and nested arrays panic during iteration.

P0013 Callers can silently lose data or panic on valid JSON. Source inspection confirms the same mistake in both `try_get_*` variants; lazy accessors delegate to them.

P0014 include the header, preferably through a shared container-slicing helper.

P0031 Pretty serialization emits invalid JSON for tuple enum variants

P0032 [src/serde/se/pp.rs:236](/work/crate/src/serde/se/pp.rs:236).

P0033 Tuple variants need both the array and enclosing object closed. The implementation writes only `}` for nonempty variants and omits the outer closing delimiter for empty variants.

P0034 Executed evidence: pretty serialization of `Pair(1,2)` produces `{"Pair":[1,2}` after removing whitespace; `Empty()` also produces incomplete JSON. Nested tests additionally show indentation state leaking into the parent.

P0035 Callers receive successful serialization results that JSON readers reject.

P0036 close both containers and restore both indentation levels; test empty, nonempty and nested variants.

P0037 Empty containers with unknown lengths are left open

P0038 [src/serde/se.rs:96](/work/crate/src/serde/se.rs:96), [src/serde/se/pp.rs:521](/work/crate/src/serde/se/pp.rs:521).

P0039 An empty sequence or map must serialize completely even when its length was initially unknown. `first` currently conflates “no elements written” with “closing delimiter already written.”

P0040 Executed evidence:

P0041 - An empty sequence using `serialize_seq(None)` returns `"["`.
- Pretty serialization of an empty struct containing a flattened map returns `"{"`.

P0042 Both calls return `Ok`, so callers can write unusable output without noticing.

P0043 track whether the container was already closed, independently of whether elements were written.

P0044 Tuple deserialization can consume a sibling’s value incorrectly

P0045 [src/serde/de.rs:254](/work/crate/src/serde/de.rs:254); sequence visitor at line 240.

P0046 Tuple lengths and container boundaries must be enforced. The requested tuple length is ignored, and successful visitors are not checked for unconsumed elements.

P0047 Executed evidence: deserializing `[[1,2],3]` as `((u8,),u8)` returns `Ok(((1,),2))`; `serde_json` rejects it. The actual sibling value `3` disappears.

P0048 validate tuple lengths and container consumption before returning from visitors. Apply the check to tuple structs, variants and other container entry points too.

P0049 Large exponents wrap into unrelated finite values

P0050 from_slice accepts a second JSON root after the requested value. src/serde.rs:61. The public from_slice function returns directly from T::deserialize without checking that the input has ended. As a result, deserializing true false into serde_json::Value succeeds with true, and {} {} succeeds with the first empty object. Callers expecting one complete JSON document receive success even though the buffer contains an additional root value.

P0051 [src/numberparse/correct.rs:186](/work/crate/src/numberparse/correct.rs:186).

P0052 The exponent must retain its mathematical meaning. Casting the accumulated `i64` exponent to `i32` wraps it.

P0053 Executed evidence:

P0054 - `1e4294967296` returns `1.0`, instead of an overflow error.
- `1e-4294967296` returns `1.0`, instead of underflowing to zero.
- Neighboring exponents return `10.0` and `0.1`.

P0055 Callers receive silently incorrect numbers.

P0056 check the conversion or use the slow parser when the exponent exceeds the fast path’s range.

P0057 Slow number paths accept invalid suffixes

P0058 [src/numberparse/correct.rs:171](/work/crate/src/numberparse/correct.rs:171), large-integer return at line 239.

P0059 Every number path must validate its terminator. Large integers and an early floating-point fallback bypass that validation.

P0060 Executed evidence: all these invalid inputs are accepted:

P0061 - `1234567890123456789x`
- `[1234567890123456789x]`
- `12345678901234567890.0x`

P0062 The suffix is silently discarded, contradicting the parsing APIs’ invalid-JSON error contract.

P0063 validate the terminator before selecting any conversion path.

P0064 Invalid surrogate sequences silently change string contents

P0065 [src/stringparse.rs:57](/work/crate/src/stringparse.rs:57), particularly lines 61 and 77.

P0066 Invalid surrogate sequences should produce an error. Missing low surrogates return a zero sentinel that becomes a NUL character; the second code unit also lacks an upper-bound check.

P0067 Executed evidence:

P0068 - `"\ud800"` becomes `"\0"`.
- `"\ud800x"` becomes `"\0x"`.
- `"\ud800\ue000"` becomes U+10400.

P0069 `serde_json` rejects these cases. Callers receive changed text instead of a parsing error.

P0070 return an error for incomplete pairs and require the second code unit to lie in `LOW_SURROGATES`.

P0071 Consuming DOM conversion rejects integer map keys

P0072 [src/serde/value/owned/de.rs:189](/work/crate/src/serde/value/owned/de.rs:189), [src/serde/value/borrowed/de.rs:202](/work/crate/src/serde/value/borrowed/de.rs:202).

P0073 Maps with integer keys should round-trip through the Serde DOM conversion APIs. Consuming conversion deserializes keys as ordinary string values, bypassing the integer-aware key deserializer.

P0074 Executed evidence: a `BTreeMap<u32,String>` successfully converts into either DOM, but consuming conversion back fails with “string `"42"`, expected u32.” Both reference conversion variants succeed.

P0075 reuse `MapKeyDeserializer` for consuming object access.

P0076 Borrowed DOM deserialization unnecessarily requires borrowed keys

P0077 [src/serde/value/borrowed/de.rs:483](/work/crate/src/serde/value/borrowed/de.rs:483).

P0078 `BorrowedValue` supports owned strings, so its Serde implementation should accept keys that cannot be borrowed. Requesting every key as `&str` prevents this.

P0079 Executed evidence: deserializing an owned `serde_json::Value` object fails, as does `serde_json::from_str::<BorrowedValue>` for an escaped key such as `"a\"b"`.

P0080 Ordinary Serde interoperability therefore depends unexpectedly on how keys are supplied.

P0081 deserialize keys with an owned-string fallback, while preserving borrowing where available.
