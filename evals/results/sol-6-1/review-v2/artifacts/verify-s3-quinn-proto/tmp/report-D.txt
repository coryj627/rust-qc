P0179 Disabling incoming connections panics on pending connections

P0180 [endpoint.rs:211](/work/crate/quinn-proto/src/endpoint.rs:211), also line 540.

P0181 `set_server_config` is documented as affecting new incoming connections only. After receiving an `Incoming`, calling `set_server_config(None)` makes both a subsequent packet for that pending connection and `accept(incoming, …, None)` unwrap the absent configuration.

P0182 An application temporarily disabling new connections can therefore panic while processing an already pending connection.

P0183 Evidence: executed `review_disable_server_handles_pending_retransmission` and `review_disable_server_preserves_pending_accept`; both panicked at the locations above.

P0184 retain the configuration associated with pending incoming connections, or handle its absence through an explicit error path.

P0185 A rejected ordered read destroys buffered stream data

P0186 [connection/streams/recv.rs:269](/work/crate/quinn-proto/src/connection/streams/recv.rs:269).

P0187 `Chunks::new` removes the receive state before checking whether ordered reading is allowed. When `ensure_ordering` returns `IllegalOrderedRead`, the removed state is dropped instead of restored.

P0188 Expected: reject the ordered read while allowing subsequent unordered reads. Observed: subsequent reads return `ClosedStream`, losing remaining buffered data.

P0189 Evidence: executed `review_illegal_ordered_read_preserves_stream`: send `hello`, read `h` unordered, attempt an ordered read, then resume unordered reading. The final read returned `ClosedStream` instead of `ello`.

P0190 validate ordering before removing the entry, or restore it on error.

P0191 Truncated optional transport parameters panic instead of returning errors

P0192 [transport_parameters.rs:472](/work/crate/quinn-proto/src/transport_parameters.rs:472), also line 479.

P0193 The `max_datagram_frame_size` and `min_ack_delay` branches unwrap integer decoding results. Empty or truncated values therefore panic instead of returning the existing malformed-parameter error.

P0194 Ordinary callers handling malformed handshake parameters cannot rely on the fallible parsing API.

P0195 Evidence: executed public-API probes confirmed panics for `20 00`, `20 01 40`, and a zero-length `min_ack_delay` parameter. Source inspection also establishes that the rustls adapter calls this parser.

P0196 decode within the advertised parameter length, propagate decoding errors, and require complete consumption of that value.

P0197 CID validation panics on short connection IDs

P0198 [cid_generator.rs:147](/work/crate/quinn-proto/src/cid_generator.rs:147).

P0199 `ConnectionIdGenerator::validate` returns `Result<(), InvalidCid>` and is intended to determine whether a CID could have been generated. `HashedConnectionIdGenerator` instead unconditionally splits at byte three.

P0200 Evidence: executed public-API probes with valid `ConnectionId` objects of lengths 0, 1, and 2; all panicked with `mid > len`.

P0201 Callers checking arbitrary CIDs receive a panic instead of `InvalidCid`.

P0202 reject lengths other than the generator’s eight-byte CID length before splitting.

P0203 Medium

P0204 Rejected 0-RTT data permanently consumes the send window

P0205 [connection/streams/state.rs:244](/work/crate/quinn-proto/src/connection/streams/state.rs:244).

P0206 `zero_rtt_rejected` clears outgoing streams and resets `data_sent`, but leaves `unacked_data` charged for the discarded early data. Those bytes can never subsequently be acknowledged.

P0207 Expected: the application can resend after rejection. Observed: filling the send window with early data leaves later writes blocked after the handshake succeeds.

P0208 Evidence: executed `review_zero_rtt_rejection_restores_send_window`, adapted from the existing rejection test. With a 13-byte send window and 13 early bytes, the subsequent write returned `Err(Blocked)` instead of `Ok(13)`.

P0209 release the discarded early data’s send-window accounting during rejection.

P0210 Stopping a reset receive stream can strand its concurrency slot

P0211 [connection/streams/mod.rs:154](/work/crate/quinn-proto/src/connection/streams/mod.rs:154).

P0212 `RecvStream::stop` frees a completed/reset receive stream without queuing the resulting `MAX_STREAMS` update. Unlike the read-finalization and `received_reset` paths, it does not call `queue_max_stream_id`.

P0213 Evidence: executed `review_stop_reset_stream_replenishes_stream_credit`. With a one-stream limit, the client resets an empty stream, the server accepts and stops it, and both endpoints are driven. Opening the next client stream still returns `None`.

P0214 An application discarding reset streams can stop accepting further streams until unrelated incoming traffic triggers an update.

P0215 queue stream-limit updates when `stop` frees receive state.

P0216 Stop followed by reset releases receive credit twice

P0217 [connection/streams/state.rs:356](/work/crate/quinn-proto/src/connection/streams/state.rs:356).

P0218 Stopping an unread stream already releases credit for its discarded bytes. Processing the subsequent reset releases `final_offset - bytes_read` again, including those same bytes.

P0219 Evidence: both an internal accounting regression and an end-to-end regression failed. With a 16-byte receive window, stopping and resetting eight unread bytes allowed the peer to write another **24 bytes**, rather than 16.

P0220 This defeats the configured buffering bound during normal stream cancellation.

P0221 for stopped streams, release only credit attributable to newly learned final-offset bytes.

P0222 Shrinking then expanding the receive window grants excess credit

P0223 [connection/streams/state.rs:873](/work/crate/quinn-proto/src/connection/streams/state.rs:873).

P0224 Expansion increases `local_max_data` without first cancelling outstanding `receive_window_shrink_debt`.

P0225 Evidence: executed internal and end-to-end regressions. Changing an unused receive window from 100 to 50 and back to 100 allowed a peer write of **150 bytes**, although no data had been consumed.

P0226 Repeated adjustments can advertise credit beyond the intended window.

P0227 cancel outstanding shrink debt before adding any net increase to advertised credit.

P0228 Datagram eviction ignores the incoming datagram’s size

P0229 [connection/datagrams.rs:39](/work/crate/quinn-proto/src/connection/datagrams.rs:39).

P0230 The eviction loop checks only the bytes already queued. It then appends the new datagram, exceeding `datagram_send_buffer_size` rather than making space as documented.

P0231 Evidence: executed `review_datagram_drop_makes_room_for_new_data`. With an eight-byte buffer, queuing `12345678` followed by `x` with dropping enabled transmitted the older datagram instead of evicting it.

P0232 Callers receive weaker memory bounds and stale-data eviction than configured.

P0233 include the incoming length in capacity accounting and explicitly handle individual datagrams larger than the buffer.

P0234 Valid wider integer encodings are rejected

P0235 [transport_parameters.rs:487](/work/crate/quinn-proto/src/transport_parameters.rs:487).

P0236 The parser compares the advertised value length against `value.size()`, which computes the minimum encoding length. QUIC variable-length integers may use wider encodings.

P0237 Evidence: an executed public-API probe accepted `04 01 01` but rejected the equivalent `04 02 40 01` with `Malformed`.

P0238 A conforming peer using a wider encoding can therefore fail transport-parameter negotiation.

P0239 validate bytes actually consumed within the parameter’s length, rather than comparing against the decoded value’s minimum size.

P0240 BBR’s bandwidth estimate never ages out a higher sample

P0241 [congestion/bbr/bw_estimation.rs:65](/work/crate/quinn-proto/src/congestion/bbr/bw_estimation.rs:65).

P0242 The rolling maximum receives updates only when a sample exceeds its current maximum. Lower samples never advance the filter, so an old peak cannot expire.

P0243 Evidence: executed `review_bandwidth_estimate_ages_out_old_peak`. After establishing 1,000,000 bytes/s and providing 25 subsequent rounds at 100,000 bytes/s, the ten-round filter still reported 1,000,000 bytes/s.

P0244 Source inspection shows that BBR uses this estimate for its target congestion window and reported pacing rate. Callers selecting the experimental BBR controller can retain an inappropriate model after available bandwidth falls.

P0245 feed all non-application-limited samples into the rolling filter; also permit higher application-limited samples.
