# Evidence export and reconstruction

The published evidence uses an explicit allowlist: reports, model-visible
messages, sandbox commands and concise logs, provenance checks, and retained
probe sources. Authentication, profiles, session events, reasoning, server
stderr and thread identifiers are excluded. Host paths and identifying strings
are scrubbed in presentation copies. Model inputs and original grading evidence
are never rewritten by this export processing.

## Retained sources

`executable-source-checks.json` records hashes of retained Rust, Python and shell
sources against the original sandbox workspaces. These sources must match before
publication. A privacy-redaction issue initially replaced synthetic email
literals inside executable Git2 fixtures. `fixture-literals.json` records the
explicitly reviewed reserved-domain literals restored for those fixtures and
their source/export hashes. Other redaction remains active. Redacted transcripts
are presentation evidence; use the retained probe sources when reproducing a
command that originally wrote a source file.

## Unchanged baseline copies

Scratch copies often contain thousands of unchanged input files. Rather than
publish duplicate or privacy-redacted copies of those inputs,
`baseline-copies.json` identifies each omitted copy by run, project, destination,
path in the pinned prepared template, and SHA-256. A file is omitted this way
only when its original workspace bytes equal the template bytes exactly.

Use the same pinned **prepared template**, including its frozen lockfiles and
dependencies, rather than a current upstream checkout. In a fresh reproduction
workspace, clone that template for the run, overlay `artifacts/<run>/`, and copy
each relevant baseline record from:

```text
templates/tmpl-<project>/<baseline_path>
```

to:

```text
projects/<run>/<destination>
```

Verify the source SHA-256 against the record before copying. Apply any
`deleted_from_template` entries in `export-index.json` only to this fresh clone.
These records describe export omissions; the original evaluation workspaces and
templates were preserved.

## Generated data and build caches

Compiled binaries, build caches and files larger than the export limit are
omitted. The artifact exclusion review identifies large baseline fixtures and
the retained generators for large boundary inputs. Sparse ZIP64 inputs can be
regenerated from their recorded probe sources and commands. Git fixture metadata
is regenerated by the probes. A compiled smoke-test executable is represented
by its source and exact compile command.

All Rust compilation and probe execution must use the unchanged `sb` sandbox,
the recorded image/toolchain and the same resource limits. The v2 grading shim
changes only the build-cache namespace and shares the original three-slot
locks. Do not install toolchains or components. Disposable cache removal happens
only after a finished run's evidence is exported and validated; it does not
remove source workspaces or probe inputs.
