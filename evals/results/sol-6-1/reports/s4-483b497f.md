1. **[P1] `--dry-run` executes `shell()` commands.** [function.rs:548](/work/crate/src/function.rs:548) calls `run_command` without checking `dry_run`. A justfile containing `x := shell('touch marker')` creates `marker` during `just --dry-run main`. Backticks correctly suppress execution. 2. **[P1] The default chooser permits shell injection through the justfile path.** [subcommand.rs:243](/work/crate/src/subcommand.rs:243) interpolates the path into shell source without escaping it. 3. **[P2] Caching parsed files by path mixes up module identities and overrides.** [compiler.rs:19](/work/crate/src/compiler.rs:19) reuses an AST containing context-specific module paths and variable numbers. With `mod a 'common.just'` and `mod b 'common.just'`, invoking both modules’ recipes prints module path `b` only once. Separately, when two modules import the same variable declaration, overriding `a::x=first b::x=second` makes both modules see `second`.

4. **[P2] Parent bindings can shadow unevaluated local assignments.** [evaluator.rs:411](/work/crate/src/evaluator.rs:411) searches the parent scope before resolving local assignments. For `A := HEX` followed by `HEX := 'custom'`, `--evaluate` gives `A` the built-in hexadecimal alphabet instead of `custom`. The same problem occurs when a submodule redeclares a parent variable, making results depend on evaluation order.

5. **[P2] `--fmt` removes module privacy.** [item.rs:59](/work/crate/src/item.rs:59) ignores the module’s `private` field when formatting. Formatting `[private]` followed by `mod hidden` removes the attribute; afterward, the previously hidden module appears in `--list`.
