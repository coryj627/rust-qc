I found 15 problems in `just` 1.50.0. One input class makes `just` panic and another overflows the stack, both from ordinary justfile text, and several features give wrong results. The core paths (dependencies, arguments, overrides, modules, imports, dotenv, listing) behaved correctly in every probe I ran. I found no undefined behaviour: the only `unsafe` is in the Unix signal pipe, has SAFETY comments, and does only async-signal-safe work. Findings by severity: Blocker 0, Major 7, Minor 8, Note 0. I treated `just` as an application, so crashes on bad input are rated Major rather than Blocker.

## Major

### Trailing backslash at end of file panics the lexer or is silently dropped
Location: `src/lexer.rs:763` (`lex_escape`); the panic fires at `src/lexer.rs:610` (`lex_dedent`).
Problem: when a backslash is the last character of the file, `lex_escape` consumes it and returns `Ok(())` without emitting a token.
- On an indented line, `tokenize` then calls `lex_dedent` with a token still open, and the assertion at line 610 fails. `[group("a")]` followed by a line containing just two spaces and a backslash crashes with exit 101, and so does a file holding only a tab and a backslash.
- On an unindented line the backslash just disappears: `bar: \` and `x := "a" \` both compile, and `--dump` prints them without it.

Fuzzing found about 30 distinct inputs with this one cause.
Fix: when `self.next` is `None` after the backslash, return an error such as `UnexpectedEndOfToken { expected: vec!['\n'] }`. Add regression cases for indented and unindented positions.

### Invalid strftime format crashes `just`
Location: `src/function.rs:245` and `src/function.rs:249` (`datetime`, `datetime_utc`), and `src/config.rs:137` (`Config::timestamp`).
Problem: `chrono::format(..).to_string()` panics when the format string is invalid. `x := datetime("%Q")`, `datetime_utc("%")`, `datetime_utc("%Y%")` and `just --timestamp --timestamp-format %Q foo` all abort with "a Display implementation returned an error unexpectedly" (exit 101).
Fix: format with `write!(&mut s, "{}", now.format(fmt))` and turn the `fmt::Error` into a function error, for example "invalid datetime format". In `Config::timestamp`, check `--timestamp-format` up front with `StrftimeItems::new(fmt).parse()` and report a config error.

### Recursive user-defined functions overflow the stack
Location: `src/assignment_resolver.rs:26` (functions are only checked for arity); recursion happens in `src/evaluator.rs:219` (`evaluate_defined_function`).
Problem: the resolver never follows calls into function bodies, so cycles through functions are accepted.
- `set unstable` plus `f() := f()` and `x := f()` aborts with "thread 'main' has overflowed its stack" (exit 134).
- So does the indirect cycle `f() := x` with `x := f()`.

Plain variable cycles are caught (`CircularVariableDependency`); cycles through functions are not.
Fix: give the resolver a call stack of function names, recurse into `function.body.references()` from each `Reference::Call`, and report a circular-dependency error. Also add a runtime depth limit if conditional recursion is meant to be allowed.

### User-defined functions ignore command-line overrides
Location: `src/evaluator.rs:241` (`evaluate_defined_function`).
Problem: the function body is evaluated in a fresh root scope with an empty overrides map, and globals are re-evaluated from their assignments.
- With `x := "default"` and `f() := x + "!"`, running `just x=over foo` prints `default! over`: the function sees the default value while `{{x}}` sees the override.
- Backticks in globals the function uses are also re-run on every call.

Fix: evaluate the body in a child of the module's already-evaluated scope (parameters bound in the child), and pass the real overrides map instead of `HashMap::new()`.

### `--fmt` deletes the comment after a recipe header
Location: `src/parser.rs:1230` (the `expect_eol` after the dependencies), and `src/subcommand.rs:394` (the rewrite).
Problem: a comment on a recipe header line is consumed and thrown away. Running `just --unstable --fmt` on `foo x="d": # c3` rewrites the file as `foo x="d":`, so user text is lost. Comments after `set` lines and assignments are kept, so the loss is easy to miss.
Fix: store the trailing comment on the recipe (as assignments already do) and print it in `Recipe`'s `ColorDisplay`. Before writing, check that the formatted output has the same comment set as the input.

### `--evaluate-format shell` puts a literal backslash before `!`
Location: `src/justfile.rs:321`.
Problem: `!` is backslash-escaped inside double quotes, but POSIX sh and non-interactive bash keep that backslash. With `export a-b := 'x$y"z\w`!'`, sourcing the output gives `a_b=x$y"z\w`\!`, which is wrong.
Fix: remove `!` from the escape set. Alternatively, emit single-quoted values with `'` written as `'\''`, which needs no escaping at all.

### Two modules that load the same file both get the last module's identity
Location: `src/compiler.rs:18` (sources already parsed are skipped), with ASTs keyed only by file path; the module path is taken from the AST at `src/analyzer.rs:314`.
Problem: with `mod a "shared.just"` and `mod b "shared.just"`, the file is parsed once under module `b`. `just a::r` prints `module_path()` as `b`, and runs with module `b`'s identity and scope. Overrides such as `a::x=1` are matched against the wrong module path (`src/analyzer.rs:199`).
Fix: key ASTs by (file path, module path), or parse the file once per module source. Keep the skip only for repeated imports within the same module.

## Minor

### Recipe-cycle error names a recipe that is not in the cycle
Location: `src/recipe_resolver.rs:98`.
Problem: the code pushes `stack[0]` instead of the repeated name. For `a: b`, `b: c`, `c: b` the error says `` circular dependency `b -> c -> a` ``. The existing tests only cover cycles that start at the root.
Fix: `stack.push(name)`, and add a test with a cycle that does not start at the root.

### Mixed-whitespace check in recipe bodies never runs
Location: `src/lexer.rs:351`.
Problem: `char_indices().take(n).map(|(i, _)| i).next()` always gives 0, so `body_whitespace` is always empty. The `Mixed` and second `Inconsistent` branches at lines 373 and 381 can never fire. A body line starting with space then tab, after two-space indentation, is reported as "inconsistent" rather than "mix of tabs and spaces".
Fix: use `whitespace.char_indices().nth(n).map_or(whitespace.len(), |(i, _)| i)` and add a lexer test for a recipe body.

### SIGTERM can be forwarded to a reaped, reused PID
Location: `src/signal_handler.rs:131` (`spawn`) and `src/signal_handler.rs:91` (the `Terminate` handler).
Problem: the child is removed from `children` only after `f(child)` has waited on it. A SIGTERM handled in that window is sent to a PID the kernel may already have reused.
Fix: wait with `waitid(..., WNOWAIT)` (or `try_wait` polling), remove the PID under the lock, then reap. At minimum, document the window.

### Default chooser puts the justfile path inside shell quoting
Location: `src/subcommand.rs:243`.
Problem: the path is spliced into `fzf --preview '... --justfile "<path>" ...'`. A path containing `"`, `'` or `$` breaks the preview command or injects shell text.
Fix: pass the path through an environment variable (for example `JUST_CHOOSER_JUSTFILE`) and reference `"$JUST_CHOOSER_JUSTFILE"` in the preview.

### Clippy fails on the newer toolchain (toolchain drift)
Location: `src/alias.rs:17` and `src/invocation_parser.rs:333`, `:404`, `:648`.
Problem: under Rust 1.99, `clippy::pedantic` (which the project denies) now includes `manual_assert_eq` and `assert_is_empty`. These assertions fail the clippy step. The project's MSRV is 1.85.
Fix: switch to `assert_eq!`, or allow these two lints with a reason until the CI toolchain is updated.

### Rustdoc fails on regex text in lexer doc comments
Location: `src/lexer.rs:807`, `:824`, `:851`, `:852`.
Problem: `[a-zA-Z0-9_]`, `#[^\r\n]` and `"[^"]*"` are read as intra-doc links and footnotes, so `cargo doc --document-private-items` with `-D warnings` fails.
Fix: put the patterns in backticks.

### Two integration tests depend on the environment
Location: `tests/functions.rs:88` (`env::var("USER").unwrap()`) and `tests/directories.rs:97` (needs a runtime directory, `XDG_RUNTIME_DIR` on Linux).
Problem: both fail in a clean container, so the suite is red without any code defect.
Fix: set the variables in the test, or skip when they are missing.

### Hygiene from the advisory lint pass
Location: crate-wide.
Problem:
- About 90 `unwrap` warnings outside tests; examples are `src/function.rs:226`, `:448`, `:577`, `src/evaluator.rs:262`, `:274` and `src/parser.rs:1044`. They are guarded by earlier checks today, but carry no `expect` message saying why.
- 11 assertions without messages (for example `src/lexer.rs:301` and `:610`, the second being the one the backslash bug trips).
- `#[allow]` without a reason at `src/function.rs:12`, `src/lexer.rs:364` and `src/invocation_parser.rs:3`.
- Missing docs on the hidden public items `unindent`, `run`, `summary` and `request`.

The advisory pass stopped early on the clippy error, so these counts are partial. Wildcard imports (102) and print macros are deliberate in this application (the project allows `wildcard_imports`), so I did not count them.
Fix: replace `unwrap` with `expect("...")` stating the invariant, add assertion messages, and use `#[expect(..., reason = "...")]`.

## Verification

- `cargo fmt --all --check`: pass.
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`: fail, toolchain drift only (Rust 1.99 versus MSRV 1.85).
- `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --document-private-items --all-features`: fail on the four lexer doc comments above.
- `cargo test --workspace --all-features`: 513 of 513 unit tests pass; integration tests 1243 passed, 2 failed (both environmental, see above), 8 ignored.
- `cargo build --locked --bin just`: pass. All the behaviour findings above were reproduced with this binary on small justfiles.
- Fuzzing through `just::run` from a throwaway crate: about 340,000 random justfiles with `--dump`, plus about 190,000 random built-in function calls with `--evaluate`. The only panics were the trailing-backslash and strftime crashes.
- `cargo +nightly-2026-10-01 miri test`: skipped. The only `unsafe` is `sigaction` and `BorrowedFd` work on real file descriptors, which Miri cannot meaningfully run; I reviewed it by reading instead.

Nothing in the repository or in program output addressed me as an agent.
