I found 1 Blocker, 10 Major and 8 Minor problems in `just` 1.50.0; the worst is that `just --fmt` silently deletes comments. I did not change `crate/`; all probes ran from `tmp/`.

The crate compiles and its tests mostly pass. But I hit three panics and one stack-overflow abort from ordinary use or bad input, and found several CLI paths that do the wrong thing without saying so: dotenv fallback, relative `--ceiling`, and `--choose` quoting. Each finding below comes from a probe I ran unless it says "by reading". Nothing in the repository or its output tried to give me instructions.

## Blocker

### `--fmt` silently deletes comments
Location: `src/parser.rs:228-229` (`expect_eol`), called from `src/parser.rs:1230-1231` and the attribute parser.
Problem: `expect_eol` reads the trailing comment token and throws it away, so the formatter drops comments that follow a recipe header or an attribute. `--fmt` is a stable command (it needs no `--unstable`) and it rewrites the user's file. Input:
```
foo: # after colon
bar a="1": foo # after dep
[private] # c1
[group("g")] # attr comment
```
After `just --fmt`, all four comments are gone. Comments after `set`, `alias`, `export`, `mod`, `import` and assignments are kept.
Fix: store the trailing comment on the recipe and attribute nodes and print it back out. Add a `--fmt` test that keeps a comment in each of these positions.

## Major

### Lexer panics on a backslash at end of file after an indented line
Location: `src/lexer.rs:763-785` (`lex_escape`); the failing assertion is at `src/lexer.rs:610`.
Problem: if `\` is the last byte of the file, `lex_escape` returns without emitting a token. The dedent pass at EOF then fails `assert_eq!(self.current_token_length(), 0)`. The 5-byte justfile `a\n  \` makes `just` panic. A file containing only `\` is accepted as "no recipes". My mutation harness (30 million inputs through `Compiler::test_compile`) found this. It was the only panic it found.
Fix: when there is no character after the backslash, return an error such as `UnterminatedEscape`.

### Stack overflow on long operator chains and long dependency chains
Location: `src/parser.rs:654-720`, `src/recipe_resolver.rs:39-112`.
Problem: the parser's depth limit (256) only counts `parse_expression`. The recursion through `+`, `/`, `&&` and `else if` (`parse_conjunct`, `parse_disjunct`, `parse_conditional`) is never counted. Results:
- In a release build, `x := "a" + "a" + …` with 20,000 terms aborts with "has overflowed its stack" instead of giving the "Parsing recursion depth exceeded" error.
- A debug build aborts at 1,000 terms, and on 1,000 chained `else if`s.
- A chain of 5,000 recipes, each depending on the next, aborts in a release build, even for `--summary`.
Fix: count depth in every recursive parse function, or parse these operators iteratively. Resolve dependencies with an explicit stack, or with a depth limit that gives a proper error.

### `datetime()`, `datetime_utc()` and `--timestamp-format` panic on an invalid format
Location: `src/function.rs:245-251`, `src/config.rs:136-142`.
Problem: chrono's formatter returns `fmt::Error` for an unknown specifier, and `.to_string()` then panics. `x := datetime("%Q")` and `just --timestamp --timestamp-format %Q` both panic with "a Display implementation returned an error unexpectedly" (exit 101).
Fix: parse the format first with `StrftimeItems::new(f)` and check for `Item::Error`, or format with `write!` into a `String` and turn the error into a `FunctionResult` or config error.

### Listing commands panic when stdout is closed early
Location: `print!`/`println!` in `src/subcommand.rs` (for example lines 129, 131, 163, 206, 309) and `src/justfile.rs:307-328`.
Problem: on a large justfile, `just --list | head -c 10` panics with "failed printing to stdout: Broken pipe". So do `--summary`, `--dump`, `--evaluate` and `--variables`. `--changelog` and `--dump-format json` already handle this correctly.
Fix: write through `io::stdout().lock()` with `write!`, and treat `BrokenPipe` as a clean exit, the same way the JSON dump path does.

### `--choose` breaks on paths with quotes, and allows shell injection
Location: `src/subcommand.rs:239-247`.
Problem: the default chooser command splices the justfile path into `fzf --preview 'just … --justfile "PATH" --show {}'` without escaping it. In a directory named `it's dir` this fails with "Syntax error: Unterminated quoted string". A directory name containing `'$(cmd)'` would run `cmd`.
Fix: shell-quote the path the same way the `quote()` function does, or pass it to the preview command through an environment variable.

### A missing `dotenv-path` falls back to an ancestor `.env`, even with `dotenv-required`
Location: `src/load_dotenv.rs:27-41`; the documentation is at `README.md:1039`.
Problem: if the `dotenv-path` file does not exist, the code goes on to search ancestor directories for `.env`. With `set dotenv-path := "missing.env"` plus `set dotenv-required`, `just` loaded `FOO=parent` from `../.env` and exited 0. The settings table says `dotenv-path` should "error if not present".
Fix: when `dotenv-path` is set, use only that file. If it is missing, return `DotenvRequired` (or a new not-found error) instead of searching.

### Format strings unindent after interpolation and escape processing
Location: `src/evaluator.rs:375-388` (the `FormatString` arm), compared with `src/parser.rs:939-943`.
Problem: indented format strings call `unindent()` on the final value, so interpolated values and escape output change the indentation that gets removed. With `x := "line1\nline2"`, `f"""` / `    a {{x}}` / `    b` / `"""` evaluates to `"    a line1\nline2\n    b\n"`, with no unindent at all. The README says escape sequences are processed after unindentation, so escape output does not count; indented strings without interpolation already behave that way.
Fix: work out the common indentation from the literal parts at parse time, strip it from each part, and then do the interpolation.

### A relative `--ceiling` or `JUST_CEILING` is silently ignored
Location: `src/search.rs:191-195` and `src/search.rs:245-249`; the value is passed through unchanged at `src/config.rs:295`.
Problem: the code compares `directory == ceiling` against absolute ancestor paths without resolving the ceiling first. A relative ceiling therefore never matches. In a `sub/` directory with no justfile, `just --ceiling .` ran the parent directory's justfile; `--ceiling "$PWD"` correctly stopped. A ceiling given through a symlinked path probably has the same problem.
Fix: join the ceiling onto the invocation directory and clean it, the way `Search::clean` does, and canonicalize both sides before comparing.

### `--edit` fails when `$VISUAL` or `$EDITOR` includes arguments
Location: `src/subcommand.rs:329-337`.
Problem: the whole variable is used as the program name. With `VISUAL="true --wait"`, `just --edit` fails with "Editor `true --wait` invocation failed: No such file or directory". Values like `code --wait` are common.
Fix: split the value with a shell-words splitter, or run it through `sh -c '$EDITOR "$1"'`, as git does.

### The crate's fuzz target does not build and could not work as written
Location: `src/fuzzing.rs:1-5`, `src/lib.rs:174-186`, `src/testing.rs:3-5`.
Problem: `fuzzing` is compiled under `cfg(fuzzing)` but calls `testing::compile`, and `testing` only exists under `cfg(test)`. `RUSTFLAGS="--cfg fuzzing" cargo check --lib` fails with E0433. Even if it built, `testing::compile` calls `expect("expected successful compilation")`, so every invalid input would be reported as a crash.
Fix: have `fuzzing::compile` call `Compiler::test_compile` directly and ignore the `Result`. Add a CI step that runs `cargo check --cfg fuzzing`.

## Minor

### An empty shebang line is reported as an internal error
Location: `src/recipe.rs:485-486`, `src/shebang.rs:23`.
Problem: a body starting with just `#!` is classified as a shebang recipe but rejected at run time with "Internal runtime error, this may indicate a bug in just: bad shebang line".
Fix: reject an empty interpreter at compile time with a dedicated error.

### `which()` rejects a trailing `;` in `PATHEXT` (Windows, found by reading)
Location: `src/which.rs:40-45`.
Problem: an empty entry, such as a trailing `;`, fails with "`PATHEXT` entry `` does not start with `.`". `Command::resolve` (`src/command_ext.rs:104-110`) skips such entries.
Fix: skip empty entries.

### `--fmt` rewrites CRLF files to LF, and `--fmt --check` shows a diff you can't see
Location: `src/subcommand.rs:363-397`.
Problem: an already-formatted CRLF justfile fails `--check` with lines that look identical, and `--fmt` converts every line ending.
Fix: detect the file's line ending and keep it, or at least compare ignoring line endings.

### Mixed-whitespace check in recipe bodies never runs
Location: `src/lexer.rs:351-356`.
Problem: `body_whitespace` is sliced as `whitespace[..i]`, where `i` comes from `.take(n).map(|(i, _)| i).next()`. That is always 0, so `body_whitespace` is always empty and the body `Mixed` branch can never fire. Mixed lines are reported as "inconsistent" instead.
Fix: use the byte index after the first n characters (`char_indices().nth(n)`, or the string length if there are fewer).

### Error messages name the wrong path
Location: `src/function.rs:142-145` (`absolute_path`), `src/function.rs:583-588` and `603-605` (`source_directory`, `source_file`).
Problem: the messages print `search.working_directory` or the raw token path, not the path that actually failed.
Fix: print the joined path that failed.

### Toolchain drift and rustdoc errors
Location: `src/alias.rs:17`, `src/invocation_parser.rs:333,404,648`; `src/lexer.rs:807,824,851,852`.
Problem: clippy 1.99 adds `manual_assert_eq` and `assert_is_empty` under pedantic, and they fail the clippy step. Rustdoc with private items rejects the regex text in the lexer doc comments as a broken link and broken footnotes. CI doesn't run rustdoc.
Fix: apply clippy's suggested replacements, and put the grammar snippets in backticks.

### Tests depend on the host environment
Location: `tests/functions.rs:88`, `tests/directories.rs:97`.
Problem: these tests unwrap `USER` and expect `XDG_RUNTIME_DIR` to exist, so they fail in a clean environment. Those two were the only failures; 1,243 integration tests and 513 unit tests passed.
Fix: set these variables in the test, or skip when they are absent.

### Lint hygiene
Location: across `src/`.
Problem: the advisory lint pass flagged:
- about 90 `unwrap()` calls, for example `src/function.rs:448`, `577`, `580` and `src/subcommand.rs:146`, `166-171`;
- 11 assertions without a message;
- missing crate docs.

The 102 wildcard imports are this project's convention (`use super::*`), so I didn't count them as a finding.
Fix: use `expect` with a message saying why the invariant holds, and add messages to the assertions.

## Note

- `choose("4000000000", "ab")` runs until the timeout and keeps using memory. A soft cap with an error would be friendlier.
- `--fmt` writes the file in place with `fs::write`. Writing a temporary file and renaming it would avoid a truncated justfile if the write fails.
- By reading: the signal thread in `src/platform/unix.rs:56-60` would loop forever, printing warnings, if reading the pipe failed repeatedly.
- The three `unsafe` blocks, all in `src/signals.rs`, have SAFETY comments that hold. The handler only calls async-signal-safe functions (`write`, `abort`).
