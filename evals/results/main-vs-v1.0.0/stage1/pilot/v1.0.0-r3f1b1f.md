# Audit report: alacritty_terminal 0.25.0

## Verdict

The escape-sequence parser held up under random input, but the crate has real defects in four areas: line editing around wide characters, size handling, the public `Grid` API, and the Unix PTY code. Five findings are Blockers. Two are panics that output from the program inside the terminal can trigger. Two are undefined behavior from safe public functions, confirmed with Miri. One is undefined behavior argued from the code but not shown. There are 5 Blocker, 10 Major, 7 Minor and 2 Note findings. The test suite passes. Rustdoc fails with warnings treated as errors.

## Blocker

### Pushing a kitty keyboard mode at full stack depth removes from the title stack
Location: src/term/mod.rs:1296 (push_keyboard_mode).
Problem: when the keyboard mode stack reaches 4096 entries, the code calls `self.title_stack.remove(0)` instead of removing from `keyboard_mode_stack`. If the title stack is empty, this panics. Otherwise it silently drops a saved title, and the keyboard stack keeps growing without limit. With `Config { kitty_keyboard: true }`, 4097 copies of `ESC [ > 1 u` from the PTY gave "removal index (is 0) should be < len (is 0)".
Fix: change it to `self.keyboard_mode_stack.remove(0)`, and add a test that pushes `KEYBOARD_MODE_STACK_MAX_DEPTH + 1` modes.

### Cursor on an orphaned wide-char spacer in column 0 overflows the column
Location: src/term/mod.rs:2377-2378 (RenderableCursor::new).
Problem: `point.column -= 1` runs whenever the cursor cell is a `WIDE_CHAR_SPACER`, including in column 0. The bytes `中` `\r` `ESC [ P` on a 4x2 terminal leave a spacer in column 0. After that, `renderable_content()` panics with "attempt to subtract with overflow" in builds with overflow checks. In release builds the renderer gets a column of `usize::MAX`. The harness found the same thing on its own (seed 116124).
Fix: only step left when `point.column > 0`. Also fix the line-editing finding below, so spacers are never orphaned.

### Zero columns write through a dangling pointer
Location: src/grid/row.rs:43-53 (Row::new), reached from the public `Row::new`, `Grid::new` and `Term::new`.
Problem: the only guard is a `debug_assert!(columns >= 1)`. With debug assertions off, `Row::new(0)` writes one element into a zero-capacity Vec. Miri, run with `-C debug-assertions=off`, reports "memory access failed ... dangling pointer" at row.rs:50 for both `Row::<Cell>::new(0)` and `Term::new(cfg, &TermSize::new(0, 1), VoidListener)`. All of these functions are safe.
Fix: replace the unsafe block with `inner.resize_with(columns, T::default)`. Or keep it, but return early or assert in release builds when `columns == 0`, and add a `// SAFETY:` comment.

### Grid::scroll_down and scroll_up accept ranges outside the screen
Location: src/grid/storage.rs:153-176 (Storage::swap), reached from the public Grid::scroll_down/scroll_up (src/grid/mod.rs:191, 252).
Problem: `compute_index` checks its bounds only with `debug_assert!`, and `swap` then calls `as_mut_ptr().add(index)` without a check. Miri reports "overflowing pointer arithmetic" for `Grid::<Cell>::new(5, 4, 100).scroll_down(&(Line(0)..Line(10)), 1)`. That is undefined behavior from safe code.
Fix: use `self.inner.swap(a, b)`, which is bounds-checked and just as fast today, or assert the indices before the unsafe block. Validate `region` against `screen_lines()` in the public scroll functions, or make them `pub(crate)`.

### getpwuid_r result is assumed initialized before it is checked
Location: src/tty/unix.rs:77-91 (get_pw_entry).
Problem: `entry.assume_init()` runs before the status and `res` checks. When the UID has no passwd entry (common in containers that run with an arbitrary UID), glibc returns 0 with `res == NULL` and may never write `entry`. That is undefined behavior. I argued this from the code and did not demonstrate it. The function is also called on every `tty::new`, even when `USER`, `HOME` and `SHELL` are all set. Separately, `status < 0` is never true: getpwuid_r returns a positive errno, so ERANGE on the 1024-byte buffer is reported as "pw not found".
Fix: check `status != 0` and `res.is_null()` first, then `assume_init`. Look up the passwd entry only when an environment variable is missing, and grow the buffer when the call returns ERANGE.

## Major

### DCH deletes the wrong cells near the end of the line
Location: src/term/mod.rs:1538-1564 (delete_chars).
Problem: `count` is clamped to `columns` instead of `columns - start`, and `end` is clamped to `columns - 1`. On a 10-column line `ABCDEFGHIJ`:
- With the cursor at column 6, `ESC [ 10 P` clears the whole row. Expected `ABCDE     `.
- With the cursor at column 9, `ESC [ 3 P` gives `ABCDEFG   `, erasing H as well. Expected `ABCDEFGH  `.
Fix: `let count = min(count, columns - start); let end = start + count;`, then shift `columns - end` cells and clear `row[columns - count..]`. Add both cases as tests.

### ED 1 does not clear line 0 when the cursor is on line 1
Location: src/term/mod.rs:1761 (clear_screen, ClearMode::Above).
Problem: `if cursor.line > 1` skips `reset_region(..cursor.line)` when the cursor is on the second line. With `AAAAA/BBBBB/CCCCC` and `ESC [ 2;3 H ESC [ 1 J`, line 0 stays `AAAAA`.
Fix: use `cursor.line > 0`.

### Copying a line that ends in a wrapped wide char takes the wrong character
Location: src/term/mod.rs:629 (line_to_string).
Problem: the wide character that belongs to a leading spacer is on the next line, but the code reads `self.grid[line - 1i32][Column(0)]`. Selecting `abc` plus the spacer on line 1 of `XYZW / abc中` returns `"abcX"`. On line 0 with no scrollback it trips the storage index assertion in debug builds and reads an unrelated row in release builds.
Fix: index `line + 1i32`. Add a test for selecting up to a leading spacer.

### ICH, DCH and ECH split wide characters and leave orphaned halves
Location: src/term/mod.rs:1187 (insert_blank), 1519 (erase_chars), 1538 (delete_chars).
Problem: these functions move or blank cells without regard to the `WIDE_CHAR` and `WIDE_CHAR_SPACER` pairing.
- `a中` followed by `ESC [ 1;3 H ESC [ @` leaves a wide char in column 1, followed by a blank cell and then a spacer.
- `ESC [ X` on column 0 of `中` leaves a lone spacer in column 1.
- DCH can move a spacer into column 0, which is what triggers the overflow Blocker above.
Fix: before editing, clear any wide char or spacer pair that straddles the edit boundaries, the way `write_at_cursor` already does.

### Sizes below MIN_COLUMNS hang or panic
Location: src/term/mod.rs:655 (Term::resize), src/grid/resize.rs:271-319 (shrink_columns).
Problem: `MIN_COLUMNS = 2` is public, but `Term::new` and `Term::resize` neither enforce it nor document it.
- Resizing a terminal that holds `中` to one column makes `shrink_columns` loop forever while allocating. It aborted after trying to allocate 640 MB.
- Resizing to 0x0 panics with a subtraction overflow.
Fix: clamp to `MIN_COLUMNS` and `MIN_SCREEN_LINES` inside `Term::new` and `Term::resize`, or return an error. Document the contract either way.

### Pty::drop can signal a reused PID
Location: src/tty/unix.rs:296-307 (Drop for Pty).
Problem: `next_child_event` calls `child.try_wait()`, which reaps the child. Later, `drop` sends `kill(child.id(), SIGHUP)` regardless. By then the PID may belong to an unrelated process.
Fix: send the signal only if `try_wait()` still returns `Ok(None)`, or record that the child has exited.

### pre_exec closure does work that is not async-signal-safe
Location: src/tty/unix.rs:236-262 and 34-55.
Problem: between fork and exec, `env::set_current_dir` allocates a CString. `set_controlling_terminal` can call `die!`, which logs through `log::error!` and then calls `std::process::exit`. That runs atexit handlers in the forked child.
Fix: convert the working directory to a CString before forking and call `libc::chdir` in the closure. On ioctl failure, return `Err(io::Error::last_os_error())` instead of logging and exiting.

### Library exits or panics on syscall failure
Location: src/tty/unix.rs:404 (on_resize, `die!`), src/tty/unix.rs:430 (set_nonblocking, `assert_eq!`), src/event_loop.rs:316 (`reregister(...).unwrap()`).
Problem: a failed TIOCSWINSZ ioctl calls `process::exit(1)` from library code. A failed fcntl or poller call panics, which kills the PTY thread. The F_GETFL result is also never checked.
Fix: return `io::Result` from these paths, or log and continue. `OnResize::on_resize` would need a fallible variant.

### Non-UTF-8 passwd fields panic
Location: src/tty/unix.rs:95-97.
Problem: `CStr::to_str().unwrap()` on `pw_name`, `pw_dir` and `pw_shell` panics for a non-UTF-8 home directory or shell path. It runs on every `tty::new`, even when the environment supplies all three values.
Fix: keep the fields as `OsString` via `OsStr::from_bytes`, or return an error.

### Unsafe blocks lack SAFETY justification
Location: about 20 blocks, including src/grid/row.rs:43, src/grid/storage.rs:159, src/term/mod.rs:2334, src/event_loop.rs:216 and src/tty/unix.rs:43, 235, 277, 299, 322, 326, 401.
Problem: none of these blocks has a `// SAFETY:` comment. Two of them are the confirmed undefined-behavior Blockers above, which shows the missing preconditions were never written down. The other blocks appear sound. `TabStops::clear_all`'s `write_bytes` over `Vec<bool>` can be `self.tabs.fill(false)`.
Fix: add SAFETY comments that state each precondition, and replace the micro-optimized blocks with safe code where it is just as fast.

## Minor

### Rustdoc fails with warnings as errors
Location: src/term/mod.rs:2272 (broken link to `Mode`), src/grid/storage.rs:145 and 147 (unescaped `Row<T>`).
Fix: link `vte::ansi::Mode` and wrap `Row<T>` in backticks.

### Clippy failure is toolchain drift outside this crate
Location: alacritty_config_derive/src/config_deserialize/de_struct.rs:177.
Problem: the lints `unnecessary_map_or` and `double_ended_iterator_last` come from a newer clippy and fail the workspace build. Nothing in alacritty_terminal is involved.
Fix: use `.next_back().is_some_and(...)`.

### Documentation gaps
Problem: about 120 public items have no docs, and about 17 functions lack an `# Errors` or `# Panics` section, for example event_loop.rs:63 and 207. `Term::new`, `Term::resize` and `Grid::new` say nothing about their size limits.
Fix: document the public surface, starting with the size and region contracts.

### Assertions, unwraps and lint overrides
Problem: about 17 assertions have no message (grid/storage.rs, grid/mod.rs:322 and 374), about 11 `unwrap()` calls are in non-test code (event_loop.rs:150 and 221), and `#[allow]` is used without a reason (grid/row.rs:117, tty/unix.rs:48).
Fix: use `expect` with a message that states the invariant, and `#[expect(..., reason = "...")]`.

### Error type drops its cause, and send errors are discarded
Location: src/event_loop.rs:380-387 and 343-347.
Problem: `EventLoopSendError::source` returns the inner error's source instead of the inner error. `Notifier` discards send failures with `let _ =`.
Fix: return `Some(err)` from `source`, and at least log failed sends.

### Library mutates the process environment and logs clipboard contents
Location: src/tty/mod.rs:95-100 (setup_env, `env::set_var`), src/event.rs:63 (Debug for Event).
Problem: `set_var` races with any other thread reading the environment. `Debug` for `ClipboardStore` prints the full clipboard text, which may be a password, into debug logs.
Fix: pass `TERM` and `COLORTERM` through `Command::env` instead. Redact the text in `Debug`, for example by printing only its length.

### Glob re-export and ASCII-art comment
Location: src/tty/mod.rs:13 and 18 (`pub use self::unix::*`), src/grid/mod.rs:84-104.
Problem: the glob re-export makes the public surface of `tty` platform-dependent and implicit. The comment in grid/mod.rs uses a drawing that a screen reader cannot follow.
Fix: re-export items by name, and describe the layout in sentences.

## Note

### No lint table, and several bare TODOs
Problem: the crate configures lints with `#![deny(clippy::all)]` in lib.rs instead of a `[lints]` table, and has bare TODOs at event.rs:84, tty/unix.rs:180 and tty/windows/conpty.rs:99.
Fix: move lints to `[lints]` in Cargo.toml and tie each TODO to an issue.

### Fuzz and Miri coverage worth adding
Random escape-sequence input (200,000 cases at legal sizes) and random vi motion, search and selection input (30,000 cases) turned up only the wide-spacer panic above. The grid unit tests pass under Miri. A seeded escape-sequence fuzz test in the suite, and `cargo miri test` on the grid module in CI, would have caught most of the Blockers.

## Verification

- `cargo fmt --all --check`: skipped. rustfmt.toml uses nightly-only options and nightly rustfmt is not installed.
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`: fail, but only in alacritty_config_derive (toolchain drift).
- `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --document-private-items --all-features`: fail, with 3 errors in alacritty_terminal.
- `cargo test --workspace --all-features`: pass. alacritty_terminal has 128 unit tests and 44 ref tests.
- `cargo +nightly miri test -p alacritty_terminal --lib grid::`: pass, 25 tests.
- `RUSTFLAGS="-C debug-assertions=off" cargo +nightly miri test`, run in a throwaway crate with tests for `Row::new(0)`, `Term::new` with 0 columns and `Grid::scroll_down` with a range past the screen: fail. Undefined behavior was reported in all three.
- The behavior probes were a throwaway binary (tmp/probe), built with overflow checks on and run against the public API. Each input that shows a problem is quoted in its finding.

Nothing in the repository or in program output tried to give me instructions. I did not change anything under `crate/`.

## Closing summary

I covered the terminal escape-sequence handlers (by reading and by random input with panic catching), grid storage and resize, selection copying, vi motions and search (random input only), all of the `unsafe` in the shared and Unix code (with Miri where it could run), and the Unix PTY and event loop for OS-level problems. I did not review the Windows PTY code beyond a grep. I did not run a full Miri pass over the whole test suite, look at serde deserialization of `Grid` as an untrusted input, or check builds at the declared MSRV of 1.74. I stopped at about 24 minutes rather than 45 because the main areas were covered with confirmed repros, and further random-input runs had stopped finding anything new.
