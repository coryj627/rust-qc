# Audit report: alacritty_terminal 0.25.0

## Verdict

The crate builds and its tests pass: 128 unit tests, 44 doc tests and the ref tests, plus the grid tests under Miri. Fuzzing and targeted probes still found real defects. Safe public constructors and grid methods can cause memory corruption. Ordinary PTY output combined with vi mode can crash the terminal. Two common erase sequences produce wrong screen contents. The Unix PTY code does unsafe work between `fork` and `exec` and can exit the host process.

Findings: 5 Blocker, 12 Major, 6 Minor, 2 Note. I did not modify `crate/`. The fuzz harness and probes are in `/work/tmp/fuzz` (`src/main.rs` and `src/bin/probe.rs`). I found no text in the repository that addressed me.

## Blocker

### Zero-column terminal or row is undefined behaviour (segfault)
Location: src/grid/row.rs:37–53 (`Row::new`), reached from `Term::new` and `Grid::new`.
Problem: `Row::new(0)` makes a zero-capacity `Vec` and then `ptr::write`s one element through its dangling pointer. The only guard is a `debug_assert!`. A zero-column `Term::new` segfaulted in a release build, and so did `Row::<Cell>::new(0)`. An embedder that creates a terminal while its window is minimised can hit this.
Fix: replace the hand-written loop with `inner.resize_with(columns, T::default)`, which is safe for 0. Separately, reject or clamp zero dimensions in `Term::new` and `Grid::new`.

### Out-of-range scroll region corrupts memory through `Storage::swap`
Location: src/grid/storage.rs:153–176 (`swap`), 220–238 (`compute_index`); public callers `Grid::scroll_up` and `Grid::scroll_down` (src/grid/mod.rs:191, 252).
Problem: `compute_index` checks bounds only with `debug_assert!`, and `swap` then reads and writes through `as_mut_ptr().add(index)` without a check. `Grid::<Cell>::new(3, 5, 10).scroll_down(&(Line(0)..Line(10)), 1)` is all safe code. In release it swapped memory outside the buffer into the grid, then panicked on a row of length 0 with index `usize::MAX`. That is undefined behaviour from safe code, and the `unsafe` block has no SAFETY comment.
Fix: turn the `debug_assert!`s in `compute_index` into `assert!`s, or implement `swap` as `self.inner.swap(a, b)`, which is bounds-checked. Validate `region` against `screen_lines` in the public scroll methods.

### Uninitialised `passwd` read when the user has no passwd entry
Location: src/tty/unix.rs:77–91 (`get_pw_entry`).
Problem: `entry.assume_init()` runs before the result is checked. When the UID has no passwd entry, `getpwuid_r` returns 0 with a null result and may leave `entry` unwritten; containers with arbitrary UIDs are a common case. That is undefined behaviour, and it runs on every `tty::new`, even when `USER`, `HOME` and `SHELL` are set. The `status < 0` test is also wrong, because `getpwuid_r` returns a positive errno, so `ERANGE` on the fixed 1024-byte buffer is never detected.
Fix: check `status != 0` and `res.is_null()` before reading `entry`, and read through `res`. Retry with a larger buffer on `ERANGE`. Look up passwd only when an environment variable is missing.

### Vi cursor left outside the grid when an app enters the alternate screen
Location: src/term/mod.rs:714–735 (`swap_alt`); crash site src/term/mod.rs:2377 (`RenderableCursor::new`), also src/term/mod.rs:902 (`expand_wide`).
Problem: the user turns on vi mode and scrolls into history, so the vi cursor sits at a negative line. When the program then sends `ESC[?1049h`, the alternate grid has no history, but the vi cursor is not clamped. The next `renderable_content()` panics, and vi motions panic too. With more than one line the index silently wraps to the wrong row instead. The fuzzer hit this many times.

Smallest reproduction:
- Terminal: 2x1 with history.
- Turn on vi mode.
- Send output `!😀`.
- Call `scroll_display(Delta(4))`.
- Send `ESC[?1049h`.
- Call `renderable_content()`: index out of bounds.

Fix: in `swap_alt`, clamp `vi_mode_cursor.point` to the new grid's bounds (`grid_clamp(self, Boundary::Grid)`). Clear or rotate it the same way the selection is cleared.

### Block selection ending on the last column panics when copied
Location: src/selection.rs:361–383 (`range_block`); crash at src/term/mod.rs:584 (`line_to_string`).
Problem: `start.point.column += 1` is not clamped. A block selection from (1, 6, Left) to (0, 6, Right) on a 7-column terminal is a mouse drag upward along the right edge. It gives a range that starts at column 7 and ends at column 5, and `selection_to_string()` panics with "len is 7 but the index is 7".
Fix: clamp the start column to `last_column` after the increment, and return `None` when start passes end. Also bounds-check `cols.start` in `line_to_string`.

## Major

### `CSI n P` (delete characters) erases text left of the cursor
Location: src/term/mod.rs:1538–1564 (`delete_chars`).
Problem: `count` is clamped to `columns` rather than to `columns - cursor`. With "abcdefgh" in 10 columns, `ESC[7G ESC[5P` gives "abcde"; the correct result is "abcdef", because "f" is left of the cursor and must survive.
Fix: `let count = min(count, columns - start);`, then derive `end` and `num_cells` from that.

### `CSI 1 J` (erase above) skips the first row when the cursor is on row 2
Location: src/term/mod.rs:1761.
Problem: the guard is `if cursor.line > 1`, so with the cursor on line 1 the line above is not cleared. With rows "AAAA/BBBB/CCCC", `ESC[2;2H ESC[1J` leaves "AAAA" on screen.
Fix: use `cursor.line > 0`.

### Copying a line that ends in a wide-character spacer appends a character from the wrong line
Location: src/term/mod.rs:623–630 (`line_to_string`).
Problem: the wide character that wrapped is on the next line, but the code reads `self.grid[line - 1i32]`. With "xyz" on line 0 and "ab中" wrapping on 3 columns, copying line 1 gives "abx" instead of "ab中". On the topmost line this indexes outside the grid.
Fix: read `self.grid[line + 1][Column(0)]` and check that `line + 1 <= bottommost_line()`.

### Resize to one column with a wide character never finishes; resize to zero columns panics
Location: src/grid/resize.rs:271–363 (`shrink_columns`), src/grid/resize.rs:378.
Problem: when shrinking to 1 column, a wide character in column 0 is swapped for a spacer and pushed into `wrapped` on every pass. The loop never ends, and memory grows until the process is killed: "中" on 4x2, then `resize` to 1x2, aborted at the memory limit. Resizing to 0 columns panics with index `usize::MAX`. The library documents no minimum size.
Fix: enforce a minimum of 2 columns and 1 line in `Term::resize` and `Term::new`, and document it. Alternatively, drop wide characters that cannot fit in one column.

### Unbounded zero-width characters per cell
Location: src/term/cell.rs:164–167 (`push_zerowidth`), src/term/mod.rs:1070–1085.
Problem: every combining mark is appended to the cell's `Vec<char>` with no limit. Program output stored 2,000,000 marks in a single cell. Memory, copying and rendering cost all grow without bound from one cell.
Fix: cap the number of zero-width characters per cell (for example 16) and drop the excess.

### Vi `M` (middle) motion is off by one and can leave the grid
Location: src/vi_mode.rs:119–124.
Problem: `screen_lines / 2 - 1` puts the cursor on the top line of a 3-line terminal and at line -1 of a 1-line terminal with no history, which is outside the grid.
Fix: `Line(-display_offset + (screen_lines as i32 - 1) / 2)`.

### Unsafe work between `fork` and `exec`
Location: src/tty/unix.rs:236–262, 34–55.
Problem: the `pre_exec` closure calls `set_controlling_terminal`. On failure that runs `die!`, which logs (allocating, formatting and locking) and then calls `process::exit`, which runs `atexit` handlers in the forked child. `env::set_current_dir` also allocates a `CString`. None of these is async-signal-safe, and in a multithreaded host they can deadlock the child.
Fix: prepare the directory as a `CString` before spawning and call `libc::chdir` in the closure. On ioctl failure, return `Err(io::Error::last_os_error())` instead of logging and exiting.

### Library exits or panics on operating-system failures
Location:
- src/tty/unix.rs:398–406 (`on_resize`: `die!`, which exits the process)
- src/tty/unix.rs:95–97 (`to_str().unwrap()` on passwd fields)
- src/tty/unix.rs:91 (`assert_eq!` on the UID)
- src/tty/unix.rs:430 (`assert_eq!` on `fcntl`)
- src/event_loop.rs:316 (`reregister(...).unwrap()`)

Problem: a failed `TIOCSWINSZ` on a resize ends the whole host application. A non-UTF-8 home directory or shell in passwd panics.
Fix: return or log errors (`OnResize` can log and continue). Use `to_string_lossy()` or an `OsString` for passwd fields, and propagate the `fcntl` and `reregister` errors.

### SIGHUP may go to a reused PID
Location: src/tty/unix.rs:296–307 (`Drop for Pty`), with src/tty/unix.rs:382 (`try_wait`).
Problem: `next_child_event` reaps the child through `try_wait`. `Drop` then sends `kill(child.id(), SIGHUP)` regardless, and the kernel may already have given that PID to an unrelated process.
Fix: skip the `kill` when `try_wait()` already returned `Some`, for example by tracking an `exited` flag.

### `setup_env` changes the process environment from a safe public function
Location: src/tty/mod.rs:92–101.
Problem: `env::set_var` races with `getenv` on other threads, which is undefined behaviour in libc and the reason it is `unsafe` in edition 2024. It also changes `TERM` for the whole host process rather than only for the child.
Fix: return the values, or set them on the child `Command` with `builder.env("TERM", ...)` in `from_fd`.

### Undocumented `unsafe` (17 blocks)
Location: for example src/grid/storage.rs:159, src/grid/row.rs:43, src/term/mod.rs:2334, src/tty/unix.rs:43, 77, 235, 299, src/event_loop.rs:216.
Problem: no block has a SAFETY comment. Two of them are unsound (the first two Blockers), and `TabStops::clear_all` uses `ptr::write_bytes` where `self.tabs.fill(false)` does the same thing.
Fix: add SAFETY comments that state each invariant, and remove the unsafe blocks that safe code can replace (`swap`, `Row::new`, `clear_all`).

### Wrong error-chaining in `EventLoopSendError::source`
Location: src/event_loop.rs:375–382.
Problem: it returns `err.source()` instead of `Some(err)`, so callers lose the underlying `io::Error` or `SendError` from the error chain.
Fix: `EventLoopSendError::Io(err) => Some(err)`, and the same for `Send`.

## Minor

### Rustdoc fails under `-D warnings` with private items documented
Location: src/term/mod.rs:2272 (broken link to `Mode`), src/grid/storage.rs:145 and 147 (unescaped `Row<T>`).
Fix: escape them as `` `Row<T>` `` and link `ansi::Mode`. Clippy's only failures are in the sibling crate `alacritty_config_derive` (`map_or` and `last` lints from a newer toolchain). That is toolchain drift outside this crate, and it stops clippy before it reaches alacritty_terminal.

### Missing documentation
Location: crate-wide. 118 public items have no docs: 38 methods, 26 fields, 14 associated functions, 13 structs, 13 variants, 6 modules and others. 10 functions returning `Result` lack `# Errors`, and 4 lack `# Panics`, for example `RegexSearch::new` (src/term/search.rs:34), `EventLoop::new` and `Selection::new`.
Fix: document the public API, including the case rule in `RegexSearch::new`: an uppercase letter anywhere in the pattern makes the search case-sensitive.

### Public types without `Debug` (16)
Location: for example src/event.rs:107, src/event_loop.rs:46, 334, 385, and `RenderableContent` and `RenderableCursor` in src/term/mod.rs.
Fix: derive or implement `Debug`.

### Assertions without messages and `unwrap` in library code
Location: 14 asserts without a message (for example src/grid/storage.rs:58–59, which assert inside `PartialEq::eq`) and 9 non-test `unwrap`s (src/event_loop.rs:150, 221; src/term/search.rs:293; src/tty/unix.rs:95–97).
Fix: use `expect` with the invariant stated in the message, or propagate the error.

### Inaccurate or drawing-based docs
Location: src/term/color.rs:14 (the grayscale ramp is listed as 233..256; it is 232..256), src/grid/mod.rs:84–104 (box-drawing diagram).
Fix: correct the range and describe the grid layout in sentences.

### Glob re-exports and narrowing casts in the PTY layer
Location: src/tty/mod.rs:13 and 18 (`pub use self::unix::*`), src/tty/unix.rs:417–421 (`as c_ushort` truncation and an unchecked `u16` multiply).
Fix: re-export items by name. Use `try_from` or saturating arithmetic for `Winsize`.

## Note

### Tests miss the defect classes above
The suite has no tests for:
- `CSI P` with a count past the end of the line
- `CSI 1 J` on row 2
- block selections at the right edge
- vi mode combined with the alternate screen
- 1- and 0-column sizes

Add these as regression tests, and keep a seeded escape-sequence fuzz loop like `tmp/fuzz` in CI.

### Miri and the feature powerset
Miri passes the existing grid tests, but they never reach the unsound paths. Add Miri tests for `Row::new(0)` and an out-of-range `scroll_down` once they are fixed. Run `cargo hack check --feature-powerset` to cover the build without `serde`.
